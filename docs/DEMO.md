# Scenariusz demonstracji — do 3 minut

Przed nagraniem uruchom projekt, przygotuj trzy niezależne profile przeglądarki i otwórz w każdym Hotel Przystań — DEMO. Na głównym ekranie włącz preferencje: brak schodów, winda, minimum 90 cm szerokości wejścia.

| Czas | Co pokazać | Proponowana narracja |
| --- | --- | --- |
| 0:00–0:20 | Wyszukiwanie i preferencje | „Samo oznaczenie dostępne nie wystarcza. Osoba na wózku potrzebuje konkretnych informacji, aby samodzielnie ocenić miejsce.” |
| 0:20–0:50 | Lista i szczegóły hotelu | „Wybieram potrzeby i widzę osobne bariery: wejście, pomiary, toaleta, istnienie i działanie windy. Na potrzeby tego scenariusza korzystamy z jawnie oznaczonych danych fikcyjnych.” |
| 0:50–1:10 | Źródła i aktualność; galeria/biblioteka | „Każda informacja ma źródło i daty. Brak danych pozostaje niewiadomą. Świeże pobranie starego rekordu nie jest nową weryfikacją.” |
| 1:10–1:40 | Zgłoszenie działania windy „Nie” | „Winda może istnieć i równocześnie nie działać. Nowa obserwacja nie nadpisuje źródła. Rozbieżność jest wyraźnie widoczna.” |
| 1:40–2:05 | Potwierdzenia z dwóch innych sesji | „Społeczność pomaga utrzymywać aktualność. To potwierdzenia sesji, nie audyt ani weryfikacja tożsamości. Konflikt pozostaje widoczny.” |
| 2:05–2:35 | Dla partnerów: JSON i widget | „Z tego samego API korzystają aplikacja, hotel i serwis turystyczny. Zmiana jest od razu dostępna również w widżecie.” |
| 2:35–3:00 | O danych / plan produktu | „Użytkownicy korzystają bez opłat. Firmy mogą płacić za integracje i usługi danych. Kolejny krok to moderacja, pilotaż z odbiorcami i regularne pozyskiwanie źródeł.” |

Jeśli internet działa, pokaż import OSM przed główną demonstracją. Jeśli nie działa, aplikacja nadal pokazuje demo i wcześniej zapisane dane. Nie przedstawiaj informacji o fikcyjnym hotelu jako faktów o rzeczywistym obiekcie.

Przykładowy opis zgłoszenia: „Winda nie uruchamia się. Obsługa potwierdziła awarię o 10:15. Proszę sprawdzić przed wizytą.” Nie wpisuj nazwisk ani innych danych osobowych.

Szkic prezentacji organizatora: problem; użytkownik i potrzeby; produkt A+D+E; demo; źródła i konflikty; architektura; rynek i model biznesowy; plan pilotażu; zespół i kolejne kroki. Prezentacja ma mieć maksymalnie 10 slajdów, a film maksymalnie 3 minuty.
